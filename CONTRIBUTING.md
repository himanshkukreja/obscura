# Contributing to Obscura

## Getting started

```bash
git clone <repo> && cd obscura
cp .env.example .env
docker compose up -d          # postgres, redis, minio, api, edge, worker, player
npm install
npm test                      # unit + integration; e2e runs too when the stack is up
```

`npm test` skips the end-to-end suite automatically when the stack is not reachable, so it
stays useful offline.

## Two rules that are not style preferences

### 1. FFmpeg is always a subprocess. Never a linked library.

Obscura is Apache-2.0. Practically every usable FFmpeg build is compiled with
`--enable-gpl` (required for libx264), which makes that binary **GPLv2+**. Invoking it as a
separate process over a command line is the established boundary that keeps our code free
of GPL obligations.

A well-meaning PR replacing the subprocess with a native binding (`ffmpeg.wasm`,
`fluent-ffmpeg` bindings, `libav*` FFI) would silently change the licence position of the
entire project. Such PRs will be rejected regardless of their technical merit. See
[docs/research.md](docs/research.md#6-license-analysis).

### 2. Never write anything that could leak a secret

No `console.log` of request bodies, tokens, keys or headers. New secret-bearing fields must
be added to `SENSITIVE_FIELDS` in `packages/shared/src/redact.ts`, which drives pino
redaction.

## Dependency policy

Runtime dependencies must be MIT, Apache-2.0, BSD or ISC. Copyleft is permitted only as a
separate process or container image, never as a linked library.

## Claims discipline

This project's credibility rests on being accurate about what it does and does not do.

- Never describe the overlay watermark as forensic protection.
- Never imply a SHA-256 hash can show a re-encoded copy is "fake" — it proves byte
  identity and nothing more.
- Never state or imply that video cannot be downloaded.
- If a feature reduces a guarantee, say so in the docs rather than omitting it. Subtitles
  shipping unencrypted is documented for exactly this reason.

## Tests

Write them alongside the change. Two areas get extra scrutiny:

- **Media is never mocked.** A mocked FFmpeg proves nothing about the part most likely to
  be wrong. Fixtures are generated by `tests/fixtures/generate.sh`.
- **Deletion gets adversarial tests.** The e2e suite plants an orphaned object that no
  database row references and asserts the purge finds it anyway — because the purge
  enumerates storage rather than trusting the database.

The single most important pipeline test asserts **identical segment-boundary PTS across
renditions**. A stream that fails it plays fine in casual testing and stutters on quality
switches in production. Do not weaken it.

## Architecture decisions

Anything significant gets an ADR in [docs/adr/](docs/adr/). ADRs are immutable once
accepted — supersede them rather than editing. [ADR-0012](docs/adr/0012-watermarking-overlay-only.md)
supersedes [ADR-0006](docs/adr/0006-watermarking-strategy.md); that is the pattern.

## Commits

Logically separated, present tense, explaining *why* where it is not obvious. Run
`npm run typecheck && npm test` before pushing.
